    admission under the registry mutex, checked in this order: shutting down, idempotent

  * INTERMITTENT TEST FAILURE FIXED. Symptom: once in a loaded full run,
    test_reading_while_writers_are_saving_never_sees_a_damaged_or_unreadable_history saw
    file_state "unreadable". Root cause (a real defect in aether_api/repository.py
    read_history): it read the history file twice (a probe that counts entries, then
    the load) and reported "unreadable" if the counts differed, so a writer saving
    between the two reads made a healthy history look unreadable. Fix: the pair of
    reads is retried up to HISTORY_READ_ATTEMPTS (3) times; a file that keeps changing,
    or cannot be read, is still reported "unreadable". Two deterministic regression tests
    in tests/test_api_history_persistence.py: a save between the two reads gives ok with
    both entries and two loads (failed before the fix: unreadable); a file changing on
    every attempt gives unreadable after exactly 3 loads. The original test is unchanged
    and passed on normal runs afterwards; no artificial load test was run.
  * Security review (pattern based, no values printed): no tokens or private keys in the
    tracked files; no env, key or certificate files; no tracked generated files;
