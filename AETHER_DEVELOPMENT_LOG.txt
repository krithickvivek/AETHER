3. THE CORRECTIVE CHANGES (all in tests/test_history_page.py)
--------------------------------------------------------------------------------
1. False pass fixed. The calc_hash import is no longer in the same try block as
   AppTest. The module skips ONLY when Streamlit itself is not installed. calc_hash
   is imported inside open_page(); if it is missing, open_page() raises
   AssertionError naming calc_hash (and likewise if AppTest has no _page_hash).
   Regression tests (class MissingCalcHashTests, 3 tests):
     - open_page raises an explicit AssertionError when calc_hash is missing
       (a stub module without calc_hash replaces the real one in sys.modules);
     - open_page raises an explicit AssertionError when _page_hash is missing;
     - a child process removes calc_hash and runs the History tests; the test
       requires 0 skipped, at least one failure/error, an unsuccessful result and
       a failing compatibility-guard test.
   The compatibility guard test_helper_reaches_the_history_page is unchanged.
   VERIFIED BY MUTATION: with the old defect temporarily re-introduced (calc_hash
   imported in the module-level try, open_page using it), the child-process
   regression test FAILED with "tests were skipped instead of failing: {'run': 23,
   'skipped': 23, 'failed': 0, 'errors': 0, 'ok': True}". The file was restored
   byte for byte (cmp identical) and the three regression tests then passed.
2. Internals documented accurately. The module docstring now lists exactly where
   Streamlit internals are used, three helpers only:
     open_page()      imports calc_hash (streamlit.testing.v1.app_test) and sets the
                      private AppTest._page_hash;
     show_workspace() (new) resets _page_hash to "" because after "Open" the app
                      switches to the Workspace but AppTest still remembers the
                      History page, so the next run() would show History again;
     html_text()      (new) reads element.proto.body (internal protobuf) because
                      AppTest has no public st.html accessor; used for the list rows
                      and the empty state. It replaces four inline uses.
   Everything else uses AppTest's public API and st.cache_data.clear(). The upgrade
   risk and the "fails loudly, never skips" behaviour are documented.
3. Assertions strengthened:
   - About page: its own title ("About this prototype") is present; the Workspace
     "generate" button and requirement text box are absent.
   - open_first_run() asserts app.exception is empty after clicking Open.
   - Disk integrity compares full file contents (snapshot() of every file under the
     temporary folder, byte for byte) instead of paths and sizes; used by the
     "opening changes nothing" and "Delete all keeps run folders" tests. Corrupt,
     newer-schema and wrong-shape context files are checked byte for byte too.
   - Unreadable history entries: history.load_history_report is checked for the
     reasons (entry #1 "'result' must be an object", entry #2 "schema version 2 ...
     newer AETHER"), the usable list is exactly the valid entry, the page shows only
     that entry's Open button (key open-<id>), Open works on it, and the file is
     byte-identical afterwards. (The page itself does not show the reasons: O2.)
   - Real user data: setUpClass/tearDownClass compare METADATA ONLY (existence, size,
     modified time; contents are never read) of the real .aether/history.json and
     the real ~/AETHER-projects tree before and after the class and fail if they
     differ. test_tests_use_temporary_data_only now also checks the paths resolve
     inside the temporary folder, differ from the real defaults, and that a page run
     lists the seeded temporary history. test_real_state_check_detects_changes proves
     the checker can fail (it runs against temporary stand-ins).
   - Approved run: no longer depends on the README being the default viewer file. It
     asserts the context's file list, that the selector lists exactly the generated
     files, then selects calculator.py explicitly (after show_workspace()) and checks
     the displayed code equals the file on disk (final newline ignored, because the
     viewer drops it).
4. Minor: shutil moved to module level; the long line split (no line is over 121
   characters); cached_ollama_status (@st.cache_data, 15 s, process-wide) is now
   cleared in setUp with st.cache_data.clear() so no test can see a status cached by
   another module. No interference was observed before; this is a precaution.

6. KNOWN ISSUES AND LIMITATIONS (verified status)
--------------------------------------------------------------------------------
  K35 (O1) A saved run whose folder or context cannot be loaded still opens from its
      saved result with the "saved run" banner but no message that the files and
      approval state are gone; a reopened run awaiting approval offers approve/reject
      again. Pinned by the O1 tests; behaviour unchanged by owner decision.
  K36 (O2) A damaged or unreadable history.json looks exactly like "No saved runs
      yet"; the reasons exist in load_history_report but the page ignores them.
      Pinned by the O2 tests; behaviour unchanged by owner decision.
  K34 The History tests depend on three Streamlit internals (see section 3, item 2).
      An upgrade can break them; they then fail loudly, which the regression tests
      prove for calc_hash and _page_hash. The html_text() failure mode
      (proto.body disappearing) raises AttributeError and was NOT separately tested.
  K37 The real-data check compares metadata only, so a change that keeps size and
      modified time identical would not be seen; it could also fail if the real app
      is writing to those folders while the tests run.
  Other limitations: AppTest only (no real browser); "Delete all" is tested by
  clicking the confirm button directly, not by opening the popover; the displayed
  generated code is never executed; only Streamlit 1.57 and Python 3.11.9 were
  tested; load_context and format_time are tested through the page because app.py
  is a script that cannot be imported; the child-process test costs about 4 s.
  Older open items still apply: K28 smoke-test isolation is best effort, not a
  sandbox; K29 only the child process is killed on timeout; K30 the suite is slower
  (now about 40-70 s); K31 templates are fixed content; K32 coverage should omit
  tests/ and use branch coverage (a .coveragerc is suggested, not created).
