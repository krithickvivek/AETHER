3. ARCHITECTURE (as built)
--------------------------------------------------------------------------------
React (later) -> aether_api (FastAPI, thin) -> RunRepository -> existing core
(RunStore, aether_ui.workflow/history, Workspace, developer.preview, progress_steps).
The API imports aether and aether_ui.workflow/history only (never app.py or
aether_ui.theme; a test proves Streamlit is not imported). It never saves its own
models: context.json and history.json are only written by the core, and the API
writes nothing. Streamlit is untouched.
Deviations from the plan: presenters.py and deps.py added; jobs.py and locks.py NOT
created (no writes yet, C10 "only if necessary"); no /runs list (the list is
/history, C7); one RunView model serves stored runs (source "run") and history
snapshots (source "snapshot"); actions are eligibility only; no "stale" flag yet;
/docs and /redoc disabled (they load scripts from a CDN).
Endpoints (all GET): /api/v1/health, config, planners/ollama/status, history,
history/{entry_id}, runs/{run_id}, runs/{run_id}/checkpoint[?override=],
runs/{run_id}/files, runs/{run_id}/files/content?path=, runs/{run_id}/plan.md,
openapi.json. Errors: {"error": {"code", "message", "details"}}; 404, 422, 503 (403
and 405 from the guard); a failed or cancelled run and a Developer failure are 200
run state; unexpected errors are a generic 500; saved text is scrubbed of the home
folder and AETHER's folder.
Corrections: C1 load and validate the run first, build a Workspace only for a run
with recorded files whose folder already exists; C2 LocalhostGuard (Host allow-list
localhost:8765 and 127.0.0.1:8765, plus :5173 only with --dev; Origin allow-list on
every method; non-GET needs an allowed Origin even without a body and then gets 405;
no CORS; websockets refused; bind 127.0.0.1 only, no --host option); C3 api_support
raises ImportError naming requirements-api.txt (never a skip); C4 failed-planning,
Developer-failure, invalid-runs-folder and fallback fields plus a persistent
actions.disabled_reason; C5 Pydantic schemas and OpenAPI; C6 history file_state
(ok/missing/damaged/unreadable), problems[] and per-entry context_state
(ok/missing/unreadable); C7 naming; C8 progress_steps with a synthesised RunResult,
run time and Manager log only from a history snapshot; C9 error model; C10 retry on
PermissionError (3 tries, 50 ms), no history rewrite after a failed read; C11
housekeeping; C12 recorded (React Context + localStorage, TanStack Query later, no

5. FINDINGS, RISKS AND KNOWN LIMITATIONS
--------------------------------------------------------------------------------
  K41 (NEW, core, not changed) The planner fallback reason is not stored in a run:
      start_project wraps the planner in a TracingPlanner that hides fallback_reason
      from PlannerAgent, so runs from either UI have no notes["planner_fallback"]
      and no failed "Build plan with local AI model" event; only the history
      snapshot has it. The API reads the note, then the snapshot; a test pins this.
  Open risk R1 (unchanged): history.json writes are read-modify-write and the core
      treats any read OSError as "damaged" then rewrites; with two writers
      (Streamlit plus a future write API) this could lose history. Reads are safe;
      write hardening is a Phase 3 prerequisite (owner decision).
  Limitations: read-only; eligibility flags without a decision endpoint; no jobs;
      no "stale" run flag; symlink escape is covered by the existing Workspace tests,
      not through the API (symlinks need privileges on Windows); the list loads one
      run per history entry (25 max); Ollama status makes one cached local request;
      tests use FastAPI's TestClient plus one live-server check, not a browser.
  Unchanged elsewhere: K34 tests use Streamlit internals (Task 008 helpers); K35 a
      saved run whose context cannot be loaded opens silently in Streamlit (the API
      reports context_state); K36 a damaged history.json looks empty in Streamlit
      (the API reports file_state); K37 real-data check is metadata only; K38 a
      partial write failure shows files but no message in Streamlit (the API reports
      developer_error); K39 the invalid-runs-folder error shows once in Streamlit
      (the API keeps the reason); K40 flaky timing, see below; K28-K32 smoke-test
      isolation is not a sandbox, only the child is killed on timeout, suite time,
      fixed templates, coverage should omit tests/.
  K40 (Task 011): the second failure was a machine suspension (about 95% confident:
      9,323 s log gap, child tests all ok, subprocess timeout counts suspended time);
      the first (150.9 s) fits a wall-clock jump in AppTest (about 60%), traceback
      not kept. No code change needed. Do not leave full runs unattended on a
      machine that sleeps.
