    agents.py            Agent ABC, AgentResult, Attempt, PlannerAgent (adapter)
    planner.py           Planner ABC, RuleBasedPlanner, BASE_STEPS, FEATURE_STEPS

    config.py            build_planner() from AETHER_PLANNER
    schema.py            (Task 003) SCHEMA_VERSION, SchemaError, upgrade() +
                         MIGRATIONS registry, validated build helpers shared by
                         every loader
    context.py           ProjectContext, AgentEvent, FileRecord, Approval,
                         RunStore (context.json + events.jsonl per run); loading
                         is versioned and validated
    developer.py         DeveloperAgent, Checkpoint A, template generation
    workspace.py         Path-safe file writer (7 suffixes, 100 KB/file, 50 files)
    templates/           3 templates (calculator, todo_web, library_api) and the
                         template-fit rules
  aether_ui/             workflow.py (RunResult/Stage view model), history.py
                         (.aether/history.json, max 25), theme.py (CSS/components)
  tests/                 16 unittest files (unittest; includes test_template_smoke.py,
                         which runs generated projects in isolated subprocesses)

Execution flow (single path since Task 005; CLI plan-only and the web app both use it):
  UI/CLI -> start_project() -> ManagerAgent.run_pipeline(requirement,
  [PlannerAgent, DeveloperAgent], store)
    1. understand(): requirement -> TaskBrief (keyword feature detection)
    2. Agents run strictly in list order. An agent with a `checkpoint` pauses the
       run (status awaiting_approval) until approve() + resume().
    3. Agent returns AgentResult; only the Manager applies whitelisted
       `updates` to ProjectContext and records AgentEvents; saves after each step.
    4. An exception or FAILED result marks the run failed and later agents skipped.
    5. Resume skips agents that already have a DONE event, keyed by (name, action).

Agent communication:
  Blackboard pattern. Agents never call each other. They read a shared
  ProjectContext and return an AgentResult. Handoff objects: TaskBrief, Plan,
  FileRecord. There are NO agent-to-agent messages, delegation records or
  streaming events. Events are recorded after an agent finishes. The STARTED
  status constant exists but is never emitted.

Persistence (file-based; SQLite is approved but NOT started):
  ~/AETHER-projects/<run_id>/{context.json, events.jsonl, workspace/}
  (events.jsonl is rewritten in full on every save). A second, duplicate store,
  .aether/history.json, holds RunResult copies (max 25). No locking, no database.
  Schema versioning (Task 003): every saved context.json, history entry and
  history result carries "schema_version" (currently 1). Records with no version
  are version 0 ("legacy") and load unchanged. Loading goes through
  schema.upgrade(), which applies registered migrations (kind, from_version) one
  version at a time; a newer version is refused (never overwritten). The version
  lives only in saved data, not on the in-memory dataclasses. Unknown top-level
  run fields are kept and written back; unknown nested fields are ignored with a
  warning. events.jsonl keeps its existing format (not versioned per line); it is
  derived from context.json. Version 1 = version 0 layout + the marker.

INSPECTION FINDINGS (before changes)
  - ProjectContext.to_dict() was dataclasses.asdict(); from_dict() used strict
    constructors (PlanStep(**step), FileRecord(**f), ...). Missing required keys
    raised KeyError/TypeError; unknown keys raised TypeError; no version.
  - RunStore.save() writes context.json and events.jsonl atomically; load() was a
    bare json.loads + from_dict. Nothing reads events.jsonl.
  - history.json is a JSON list of {"id", "result"}; load_history() returned []
    for any damaged file, and save_run() then OVERWROTE the damaged file with just
    the new entry (silent data loss). Entries were read with entry["result"] and
    would crash the History page if malformed.
  - Real data on this machine, checked read-only: .aether/history.json has 14
    legacy entries; ~/AETHER-projects has 1 legacy run (11 keys, no version).
  - Existing tests compare contexts with ==, so the version must not be a
    dataclass field. manager._UPDATABLE is derived from ProjectContext fields, so
    any new field would have become agent-updatable.
  - app.py catches (OSError, ValueError, KeyError) when opening a run, so the new
    error type had to be a ValueError subclass.

IMPLEMENTATION
  aether/schema.py (new)
    - SCHEMA_VERSION = 1; LEGACY_VERSION = 0 (records with no schema_version).
    - Kinds: context, run_result, history_entry; they share one version number.
    - SchemaError(ValueError).
    - MIGRATIONS registry keyed by (kind, from_version); upgrade(data, kind)
      returns a migrated COPY step by step, refuses newer or malformed versions,
      refuses a missing migration step, never mutates input.
    - Validation helpers: check_type (bool is not accepted as a number),
      check_items, build(cls, data, where, types, warnings) (required fields =
      dataclass fields without defaults; unknown keys -> warnings),
      brief_from_dict, plan_from_dict (shared by context and history loaders).
  aether/context.py (modified)
    - to_dict(): {"schema_version": 1, ...all fields..., + kept unknown fields}.
    - from_dict(): upgrade, then validate. Essential: run_id (non-empty text),
      requirement, created_at. Optional fields default safely (status running,
      lists empty, brief/plan/project_type None; null lists/notes treated empty).
      Nested records validated with their location in error messages, e.g.
      "files[0]: 'size' must be a whole number, not text."
    - Unknown top-level fields kept in context.unknown_fields (non-field
      attribute set in __post_init__, so it is outside ==, asdict and the agent
      whitelist) and written back by to_dict(). Unknown nested fields ignored with
      a warning. Unrecognised status kept with a warning.
    - event_from_dict() public; RunStore.load() wraps errors as SchemaError naming
      the run and file, warns if folder name != record run_id;
      RunStore.load_events() reads events.jsonl line by line with line numbers.
  aether_ui/workflow.py (modified; this is the history view-model, not the
    Streamlit page)
    - result_to_dict() adds schema_version; result_from_dict(data, warnings=None)
      upgrades and validates. fallback_reason and run_id remain optional.
  aether_ui/history.py (modified)
    - New history entries carry schema_version (entry and result).
    - _read_raw(); load_history_report() returns (usable upgraded entries,
      problem descriptions); load_history() keeps its signature and returns only
      readable entries (so the UI cannot crash on one bad entry).
    - save_run() keeps all existing entries EXACTLY as saved (even unreadable or
      newer-version ones) and copies a damaged file to
      history.json.damaged-<timestamp> before replacing it (fixes the silent data
      loss described above).
    - entry_to_result() upgrades/validates and raises SchemaError.
  Persistence format: preserved. Same files, same keys; the only addition is the
  schema_version key. events.jsonl format is unchanged.
