--------------------------------------------------------------------------------
Base class ErrorPathTestCase extends the Task 009 WorkspacePageTestCase (temporary
history and run folders, blocked network, submit/approve helpers). No new Streamlit
internals: toasts are read through AppTest's public app.toast; the History test
reuses the Task 008 open_page helper. Safety: INVALID_RUNS_FOLDER is a path inside
AETHER's own folder used only as the VALUE of AETHER_RUNS_DIR (RunStore resolves but
never creates it); every test asserts the folder does not exist before and after
(a cleanup assertion), nothing is deleted by the tests; environment variables change
only through mock.patch.dict with cleanup, and setUpClass/tearDownClass verify the
AETHER_* variables are back to their original values.

   1. page load with an invalid folder shows no error (the check runs only when the
      folder is needed);
   2. Generate: exactly one error "Generated projects cannot be saved: Runs cannot be
      stored inside AETHER's own folder ...", the plan IS generated (result ok) and
      saved to history with run_id None, context is None, no approve/reject buttons,
      the temporary runs folder is not even created;
   3. PINNED (K39): after any later rerun the error is gone, the plan stays on screen
      ("Plan generated by RuleBasedPlanner"), nothing on the page explains why, and
      there is still nothing to approve.
B. History-save OSError - app.py 133-134 (HistorySaveErrorTests, 3):
   4. a REAL OSError (the history file's parent is a regular file; no mocks): exactly
      one toast "The plan was generated but could not be saved to history." and no
      "Plan saved to history" toast, result ok, no error element, blocker file
      untouched, history file not created;
   5. the run is still usable: checkpoint approve enabled, approving generates the 4
      calculator files (success message, status completed);
   6. control: a working history shows exactly "Plan saved to history" (proves the
      toast assertions are meaningful) and one saved entry.
C. Runs folder becomes invalid after a run is on screen - app.py 382 and related
   (RunsFolderBecomesInvalidTests, 3). SIMULATED: AETHER_RUNS_DIR is changed between
   reruns; this cannot happen in normal use because a run only exists when the folder
   was valid, so these document a defensive branch:
   7. completed run: the error is shown again, the file selector is gone
      (render_files returned early), the context stays "completed", files on disk
      unchanged;
   8. run at the checkpoint: the error shows, approve AND reject are disabled, status
      stays awaiting_approval, nothing written;
   9. opening a completed run from History with an invalid folder: load_context
      catches the ValueError from RunStore(), so the run opens from the saved result
      only (banner, context None, no file list), history file unchanged.

      (inside AETHER's own folder), the error "Generated projects cannot be saved"

      there is no way to approve it and nothing explains why. Pinned by test 3.
      Candidate fix for a later task: keep the error, or disable/replace the
      checkpoint with an explanatory message, whenever the store is invalid.

      full-suite runs under coverage failed in code from earlier tasks, not in the

      recorded; coverage showed app.py 348-353 uncovered, which suggests an AppTest

      mitigation candidates: larger or load-aware timeouts, or running the smoke
      tests with a longer limit. No change was made.
